# Xynigo 店小秘物流助手安装与验收

## 安装

### Tampermonkey（采购物流专员推荐）

1. 在 Chrome 或 Comet 安装并启用 Tampermonkey。
2. 打开 [Xynigo 店小秘物流助手一键安装链接](https://raw.githubusercontent.com/wrangler1024/crossborder-userscripts/main/scripts/dxm-logistics-assistant/xynigo_dxm_logistics_assistant.user.js)。
3. 核对脚本名称和版本后点击“安装”。脚本权限为 `@grant none`，只匹配店小秘订单页面。
4. 刷新店小秘订单列表页，确认右侧出现“物流助手”。
5. 后续可在 Tampermonkey 管理面板点击“检查脚本更新”。

不要同时启用 Tampermonkey 版和 Chrome / Comet 扩展版。

### Chrome / Comet 扩展

1. 执行 `npm run build:xynigo-dxm-logistics:dev`。
2. 在 Chrome 或 Comet 扩展管理页开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择 `dist/xynigo-dxm-logistics-assistant-dev/`。
4. 打开或刷新任意店小秘订单列表页，页面右边缘应出现只显示 Xynigo 图标的悬浮胶囊。
5. 鼠标悬停时，胶囊应保持贴住右边缘并向左伸出“物流助手”。
6. 按住胶囊上下拖动，松开后不应误打开；普通点击应打开物流助手窗口。

## 普通发货验收

必须先用测试店和少量测试订单验收：

1. 输入 1 个不存在的订单，确认没有任何可发货订单时插件阻止执行。
2. 先停留在店小秘“筛选”页签，再执行预检，确认插件能自动切换到“搜索”并将列表收敛到本批订单。
3. 人为保留一个旧分页总数，再搜索1个目标订单，确认插件采用当前1条结果而不是旧计数。
4. 输入重复订单、重复物流号和格式错误数据，确认插件阻止执行。
5. 点击“下载导入模板”，确认模板含“订单号、物流单号、物流商渠道”三列，并且物流商列可从下拉选项选择。
6. 在模板录入包含长 USPS 单号的 1–3 条数据并上传，确认完整单号和物流商被填入输入框，且上传后不会自动预检或发货。
7. 分别上传缺字段、错误物流商、数字格式长单号及超过 300 条的文件，确认插件显示对应 Excel/CSV 行号并阻止导入。
8. 输入 1 个测试订单，核对预览中的订单号、店小秘内部包裹 ID、物流号和物流商。
9. 核对“店小秘平台承运商”来自当前订单的实时可选项；匹配不到或存在多个候选时必须阻止执行。
10. 测试 `IMILE` 输入时，预览必须显示店小秘平台承运商 `iMile`；如果只有小写 `imile`，预检必须阻止执行。
11. 不勾选风险确认，确认“执行发货”按钮不可用。
12. 分别用 SHEIN 墨西哥和美国测试订单勾选后执行，看到“店小秘已受理”后，检查“发货成功/发货失败”列表确认平台最终结果。
13. 再用 4 个测试订单，分别选择并发数 1、2、4，确认同一时刻发出的请求不超过所选值，默认选中 2。
14. 模拟店小秘返回“正在执行移入运单号申请”，确认后续请求自动降为串行，单条明确失败仍继续处理后续订单。
15. 模拟断网、超时或无法解析响应，确认该订单显示“结果未知”，插件不会自动重试，并停止派发尚未开始的订单；结果 CSV 将其标记为“未提交（已暂停）”。
16. 执行期间确认窗口实时显示进度、执行时长、初始并发、当前并发和接口繁忙次数；繁忙降级后应显示首次触发的预览行序号。
17. 执行完成后确认最终汇总显示在当前可见预览区，并记录总用时、初始/最终并发、繁忙次数和首次降级序号。
18. 输入 3 个订单，其中 2 个仍在待处理、1 个已发货或退款，确认预览显示“导入 3、可发货 2、已排除 1”。
19. 核对已排除订单显示原因且执行按钮只统计 2 条；执行后确认店小秘只收到 2 个可发货包裹 ID，结果 CSV 包含第 3 条“已排除”。
20. 模拟搜索混入非本批订单、详情回读失败、重复包裹或承运商歧义，确认这些情况仍然整批阻断。

## 失败单重提验收

1. 打开“订单—已交运—发货失败”，确认插件默认选择“失败单重提”。
2. 输入订单号、当前物流单号和物流商，确认预览显示店小秘现有承运商与失败原因。
3. 故意输入不同物流单号或物流商，确认插件阻止重提且未发出提交请求。
4. 对 `iMile` 失败单确认当前物流方式必须精确为 `iMile`；仍为小写 `imile` 时插件必须阻止重提。
5. 切换到“首次发货”，确认插件提示发货失败页禁止执行首次发货。
6. 使用测试失败单核对预览并勾选确认，再点击“确认并重新提交平台”。
7. 看到“店小秘已受理”后，回到“发货成功/发货失败”列表复核最终平台结果。

## 拆单分批发货验收

准备一个已经在店小秘手工拆成至少 3 个包裹的测试订单，其中 1–2 个采购子单已有物流，至少 1 个采购子单仍待物流。

1. 选择“拆单分批发货”，只输入已有物流的采购子单，例如 `原订单号-1`、`原订单号-3`；不要输入待物流子单。
2. 点击“读取拆分包裹”，确认店小秘搜索框只提交一次原订单号，但插件读取出该原订单的全部拆分包裹。
3. 核对每个包裹卡片的店小秘包裹 ID、状态、商品图、SKU/规格摘要；没有商品图时必须返回店小秘详情人工确认。
4. 确认第一个未匹配采购子单默认高亮；直接点击对应包裹卡片后，该卡片显示采购子单号，并自动高亮下一个未匹配子单。
5. 点击任意采购子单行后再点包裹卡片，确认可重新指定当前映射；点击“清除”应取消该行映射。
6. 少选一个映射，确认“核对本批物流”会阻止继续；选择已有物流号或不可发货状态的包裹，也必须阻止。
7. 映射完成后核对最终预览中的采购子单号、原订单号、物流单号、店小秘平台承运商和内部包裹 ID。
8. 不勾选确认时，执行按钮必须禁用；勾选后可设置并发数 1–4，并确认只对本批已映射包裹发货。
9. 回到店小秘列表确认本批包裹进入“发货成功/发货失败”，未录入、未映射的待物流包裹仍保持原状态。
10. 待剩余子单出物流后单独再提交，确认已经发货或已有物流单号的包裹不会被再次选择执行。

## 已知限制

- 插件不会自动执行店小秘拆单；必须先在店小秘页面手工按实际采购包裹完成拆分。
- 采购子单号不是店小秘字段，映射只在本次操作内存中使用，关闭窗口或刷新页面后不保存。
- 拆单失败单目前不支持在同一原订单下自动定位重提包裹；需先按店小秘包裹逐项核对，完成现场验证后再扩展。
- 当前每批最多 300 条，与店小秘列表单页可回读规模对齐；超过 300 条需拆批，避免跨页漏读。
- 插件会把输入物流商映射到店小秘当前订单的实时平台承运商选项；无法唯一匹配时必须人工确认，其他物流商仍需逐个测试店验收。
- 是否支持“不打单/导入发货”与店铺履约方式有关；团队运营的商家自履约店铺已验证可用，不能仅按墨西哥/美国站点判断。
- 店小秘受理发货请求后还会异步提交平台，插件不会把“已受理”误报为“平台发货成功”。
- 店小秘页面结构或接口参数调整后，自动搜索和发货可能失效；失效时应停止使用并重新验收。
