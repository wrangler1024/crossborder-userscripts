## P0：新会话启动与页面范围验收

- [ ] 阅读 `PROJECT_MEMORY.md` 和 `handoff.md`。
- [ ] 执行 `git status --short`，确认物流助手目录无未说明改动；保留采购助手和根 README 的用户脏文件。
- [ ] 执行 `git ls-remote origin refs/heads/main`，确认远端至少为 `737db41`。
- [ ] Tampermonkey 管理面板确认物流助手版本为 `0.3.2`；若主 Raw 链接缓存旧版，先用提交固定安装链接。
- [ ] 在店小秘“待处理” `/web/order/approved` 刷新，确认右侧只出现一个物流助手入口。
- [ ] 切到“待审核” `/web/order/paid`、发货失败和其他订单页，确认入口消失；再返回待处理页并刷新，确认入口恢复。
- [ ] 确认物流助手 UI 只显示“首次发货”和“拆单分批发货”，不显示失败单重提。

## P0：只读预检回归

- [ ] 用 1 个脱敏不存在订单测试：应提示当前待处理页未找到，不得发出发货/拆单请求。
- [ ] 用 1–3 个可发货测试订单只执行到最终预览，核对订单号、内部包裹 ID、物流号、输入物流商和店小秘平台承运商。
- [ ] 分别核对墨西哥 `J&T`、`iMile` 和美国 `USPS`、`GOFO`、`SpeedX` 的实时选项映射；不匹配时停止，不手改成猜测名称。
- [ ] 验证搜索结果混入非本批行、旧分页计数和固定列镜像行时的行为符合项目记忆。

## P0：SHEIN 自动拆单现场验收

- [!] 用户提供并明确授权一个低风险、可撤销影响已知的 SHEIN 多件测试订单；在授权前只允许读取拆单详情和查看计划，不点击最终拆单。
- [ ] 测试订单至少包含 2 件商品，并且只有部分采购子单已出物流，用于验证残余商品保留原包裹。
- [ ] 核对拆单计划展示的图片、SKU/规格、`productCount` 和采购子单数量；不得按子单序号自动猜商品。
- [ ] 在浏览器网络面板确认提交前没有 `/api/order/batchSplitOrder.json` 请求。
- [!] 用户在最终拆单动作前再次确认后，执行第一次确认；核对拆单请求只有 1 次、按原订单串行、矩阵总量守恒。
- [ ] 拆单受理后确认插件重新搜索，并且在新包裹回读完成前没有 `/api/package/withOutPrintShip.json`。
- [ ] 人工按商品图把采购子单映射到新包裹，检查未出物流残余包裹没有进入本批发货预览。
- [!] 用户在最终发货动作前再次确认后，执行第二次确认；到店小秘“发货成功/发货失败”列表复核平台最终状态。
- [ ] 记录真实响应中 `dxmOrder.productList` 的脱敏字段结构、拆单响应和新包裹数量变化；不得保存真实客户/订单数据。

## P0：异常安全验收

- [ ] 模拟拆单 5xx、超时、断网、非 JSON、缺少 code：确认不自动重试、不继续拆下一单、不发货。
- [ ] 模拟拆单返回 `code=0` 但新包裹数不等于计划：确认页面锁定并提示人工核对。
- [ ] 模拟发货繁忙：确认首次繁忙后当前并发显示为 1，剩余请求串行。
- [ ] 模拟发货结果未知：确认停止派发，剩余订单标记为暂停未提交，CSV 保留状态。
- [ ] 执行中切离待处理页：确认入口立即消失；当前写入结束后窗口移除，后续新写入被路径门禁阻止。

## P1：代码收敛

- [ ] 删除或拆出当前 UI 不可达的失败单重提代码：`MODE_RETRY`、`RETRY_COMMIT_ENDPOINT`、`prepareRetryMatches`、`retryFailedShipment` 及相应分支。
- [ ] 删除 3 个已跳过的旧失败单重提浏览器测试，或把该能力独立成只匹配发货失败页的单独插件后恢复测试。
- [ ] 清理 README/CSV 中只为旧重提模式保留的字段和文案，确保新作用域没有死功能描述。
- [ ] 为页面路径门禁增加 manifest、userscript、运行时三者版本一致性测试，禁止再次把 paid/approved 写反。
- [ ] 评估用 History API 事件替代 250ms pathname 轮询；必须先证明能覆盖店小秘 Vue SPA 的真实侧栏切换。

## P1：拆单可用性

- [ ] 为“一个原订单已有多个待处理包裹、其中仅一个仍为多件残余”的场景研究安全唯一定位规则；无法唯一识别时继续阻断。
- [ ] 拆单计划增加更明确的“原包裹残余”和“本批新包裹”汇总，减少采购误读。
- [ ] 给拆单执行增加独立耗时、当前原订单和回读重试进度记录；不要与发货并发指标混用。
- [ ] 评估拆单结果 CSV/审计记录；不得存储客户地址或 Cookie。

## P2：发布治理

- [ ] 真实测试店验收通过后再决定是否发布 GitHub prerelease；当前稳定 Release 仍是 `v0.1.14`。
- [ ] 发布时核对 manifest、package、popup、README、生成 userscript、ZIP 目录名和 Git tag 版本一致。
- [ ] 生成并记录 ZIP SHA-256；用 `unzip -l` 核对模板、图标、vendor 和共享源码齐全。
- [ ] 提交前执行 `git diff --cached --name-only` 和 `git diff --cached --check`，只包含物流助手文件且无真实数据/凭证。
- [ ] GitHub Raw 主链接若短时缓存旧版，先核对远端 HEAD 和提交固定 URL，不重复提交无意义版本。
