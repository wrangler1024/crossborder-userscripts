# Xynigo 店小秘物流助手

> 当前版本：`0.1.13`（第一期，测试店验收前不得批量用于正式订单）

## 安装

- 采购部物流专员优先使用：[Tampermonkey 一键安装](https://raw.githubusercontent.com/wrangler1024/crossborder-userscripts/main/scripts/dxm-logistics-assistant/xynigo_dxm_logistics_assistant.user.js)。打开链接后在 Tampermonkey 页面点击“安装”。
- Chrome / Comet 扩展包：[下载 v0.1.13](https://github.com/wrangler1024/crossborder-userscripts/releases/download/dxm-logistics-assistant-v0.1.13/xynigo-dxm-logistics-assistant-v0.1.13.zip)。
- 两种安装方式不要同时启用，避免页面出现两个入口。篡改猴版通过 GitHub Raw 地址自动检查更新。

## 第一期范围

- 运营粘贴“店小秘订单号 + 物流单号”，每行一单。
- 入口与采购同事使用的“Xynigo SHEIN 采购助手”一致：按钮贴住页面右边缘，默认只显示图标，悬停或键盘聚焦时向左伸出“物流助手”。
- 插件图标采用与验证码解题助手一致的海军蓝背景，并以三个黄色封箱胶带包裹汇入橙红发货箭头表达“批量自动出库”。
- 页面右侧入口采用同一海军蓝背景，移除图标外层底块；入口高度为 44px，悬停展开宽度为 124px。
- 按住悬浮按钮可上下拖动；拖动结束不会误触发打开，页面尺寸变化后会自动限制在可视区内。
- 可为本批统一选择物流商；默认使用旧流程已验证过的 `UPS`。
- 支持下载正式 `.xlsx` 模板，并上传 `.xlsx` 或 `.csv`；模板字段为“订单号、物流单号、物流商渠道”，上传仅替换输入框内容，不会直接发货。
- Comet 下载模板时先读取扩展内置文件，再通过页面 Blob 下载，不再直接打开会被 Comet 拦截的 `chrome-extension://` 文件地址。
- Excel 模板已将输入区域设为文本格式，避免 USPS 等长物流单号被转换为科学计数法或丢位；数字单元格和科学计数法会被导入校验阻止。
- “发货导入”工作表的 300 行输入区域增加浅灰色完整单元格线，方便在 WPS、Excel 中横向和逐行录入。
- 插件会先切换到店小秘“搜索”模式，以订单号精确搜索，再调用订单详情接口做精确匹配。
- 搜索模式、搜索框或搜索按钮不可用时立即停止；搜索结果仍混有本批以外订单时也会阻止预检，不再扫描当前整页订单。
- 搜索收敛以店小秘页面显示的结果总数为准；固定列或隐藏表格产生的镜像行不会再被误判为额外订单，详情仍只回读包含本批订单号的目标行。
- 预检会调用店小秘原生“不打单发货”选项接口，按订单平台读取当前可用承运商；输入物流商必须唯一匹配有效选项。
- 当前输入物流商支持 `UPS`、`USPS`、`FedEx`、`DHL`、`J&T`、`iMile`、`GOFO`、`SpeedX`，提交时仍以店小秘实时返回的精确名称为准。
- `iMile` 使用大小写敏感的严格映射：店小秘中的小写 `imile` 是另一个独立选项，不允许替代 `iMile`；失败单仍为 `imile` 时也禁止直接重提。
- 墨西哥站和美国站均按订单实时读取店小秘平台承运商；是否支持“不打单/导入发货”取决于店铺履约方式，不按国家统一拦截。
- 预览同时显示输入物流商和店小秘平台承运商；勾选风险确认并再次点击，才调用店小秘发货接口。
- 按顺序逐单发货，单条失败不影响后续订单；结果可下载为 CSV。
- 发货接口返回 `code=0` 只表示店小秘已受理，最终结果仍须到“发货成功/发货失败”列表复核。

## 失败单重提

- 在店小秘“发货失败”列表页打开插件时，默认进入“失败单重提”。
- 输入格式仍为“订单号 + 当前物流单号”，可选第三列填写物流商；插件会回读失败单现有物流号、承运商和失败原因。
- 输入物流号必须与店小秘现有物流号完全一致，输入物流商必须与现有承运商匹配；不一致时阻止重提并提示先修正物流信息。
- 确认后只调用店小秘“继续提交平台”接口 `/api/package/commitPlatform.json`，不会再次调用首次发货接口，也不会改写物流信息。
- 首次发货模式禁止在“发货失败”页执行；失败单重提禁止在其他订单页执行。

第一期不接 Xynigo 云端物流查询结果，不自动读取采购系统，也不保存输入的订单号或物流单号。后续阶段再接入 Xynigo 物流结果并增加云端幂等审计。

## 输入格式

可以点击“下载导入模板”，在“发货导入”工作表填写三列后，再点击“上传 Excel/CSV”：

```text
订单号	物流单号	物流商渠道
GSH1TEST00001A	JMXTEST000000001	J&T Express
GSH1TEST00002B	49400000000002	iMile
```

模板上传要求三列均填写，物流商渠道支持 `UPS`、`USPS`、`FedEx`、`DHL`、`J&T Express`、`iMile`、`GOFO`、`SpeedX`。插件会在本地读取文件并统一为当前输入格式，不上传到 Xynigo 或第三方服务。

推荐从 Excel 复制两列：

```text
GSU1SAMPLE0001A	1Z999AA10123456784
GSU1SAMPLE0002B	1Z999AA10123456785
```

也支持逗号、分号或多个空格分隔。可选第三列临时覆盖本行物流商，例如：

```text
GSU1SAMPLE0001A	1Z999AA10123456784	UPS
```

同一订单对应多个不同物流单号、或同一物流单号对应多个订单时，第一期直接阻止执行，避免拆包关系不明确导致错发。

当前每批最多 300 条，与店小秘列表单页可回读规模对齐。超过 300 条请拆分文件后分批操作，避免订单跨页后只回读到一部分搜索结果。

## 安全边界

- 只匹配 `dianxiaomi.com/web/order/*`，不申请 Cookie、全站网络或后台监听权限。
- 订单必须通过店小秘 `/api/order/detail.json` 回读并与输入完全一致，不能只凭列表文本模糊匹配。
- 必须通过 `/api/order/withOutPrintShippingList.json` 读取订单所属平台的实时承运商选项；不再把 `J&T` 硬编码为猜测名称。
- 平台承运商匹配失败或同时命中多个候选时阻止提交，并显示店小秘返回的候选名称。
- 不按订单国家猜测店铺履约能力；团队已验证的商家自履约店铺继续使用“不打单/导入发货”流程。
- 执行前必须预览，并勾选“已核对且确认不可撤销写入”。
- 发货请求顺序执行；仅对店小秘明确返回“正在执行移入运单号申请”做有限重试。
- 失败单重提顺序执行且不自动重试网络异常，避免接口已受理时重复提交。
- 网络中断或响应无法解析时标记为“结果未知”，不自动重试，须先去店小秘已发货列表核对。

## 复用来源

- 发货接口与参数流程来自前 IT 在 2025 年维护的 `dxm_super_logistics_tool`。
- 发货窗口批量填号思路参考现有 `scripts/dxm-ship-without-order/`。
- 本插件移除了旧深孚账号、密码、第三方物流中心、广泛主机权限和高并发逻辑，改为本批手工输入、精确预检与显式确认。
