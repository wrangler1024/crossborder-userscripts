# Xynigo 店小秘物流助手

> 当前开发版本：`0.3.2`（待处理页面限定与 SHEIN 自动拆单分批发货测试版；完成真实测试店验收前不得用于正式订单）

## 安装

- 采购部物流专员优先使用：[Tampermonkey 一键安装](https://raw.githubusercontent.com/wrangler1024/crossborder-userscripts/main/scripts/dxm-logistics-assistant/xynigo_dxm_logistics_assistant.user.js)。打开链接后在 Tampermonkey 页面点击“安装”。
- Chrome / Comet 已发布稳定包仍为：[下载 v0.1.14](https://github.com/wrangler1024/crossborder-userscripts/releases/download/dxm-logistics-assistant-v0.1.14/xynigo-dxm-logistics-assistant-v0.1.14.zip)。`v0.3.2` 须完成测试店验收后再发布为稳定包。
- 两种安装方式不要同时启用，避免页面出现两个入口。篡改猴版通过 GitHub Raw 地址自动检查更新。

## 功能范围

- 插件只在店小秘“订单—待处理”页面（`/web/order/approved`）显示和执行；“待审核”、已交运、发货失败及其他页面均不显示入口。
- 普通首次发货粘贴“店小秘订单号 + 物流单号”，每行一单。
- 拆单分批发货粘贴“采购子单号 + 物流单号”，采购子单号统一为“原订单号-序号”，例如 `GSH1SAMPLE0001A-1`。
- SHEIN 多件订单尚未拆包时，插件会读取店小秘可拆商品，由采购按商品图、SKU/规格和数量生成拆单计划；已出物流子单单独成包，未出物流商品保留在原包裹。
- 拆单和发货采用两次独立确认：第一次只执行店小秘拆单；拆单后必须重新搜索、回读并核对新包裹，第二次确认才会填写物流并发货。
- 入口与采购同事使用的“Xynigo SHEIN 采购助手”一致：按钮贴住页面右边缘，默认只显示图标，悬停或键盘聚焦时向左伸出“物流助手”。
- 插件图标采用与验证码解题助手一致的海军蓝背景，并以三个黄色封箱胶带包裹汇入橙红发货箭头表达“批量自动出库”。
- 页面右侧入口采用同一海军蓝背景，移除图标外层底块；入口高度为 44px，悬停展开宽度为 124px。
- 按住悬浮按钮可上下拖动；拖动结束不会误触发打开，页面尺寸变化后会自动限制在可视区内。
- 可为本批统一选择物流商；默认使用旧流程已验证过的 `UPS`。
- 支持下载正式 `.xlsx` 模板，并上传 `.xlsx` 或 `.csv`；模板字段为“订单号、物流单号、物流商渠道”，上传仅替换输入框内容，不会直接发货。
- Comet 下载模板时先读取扩展内置文件，再通过页面 Blob 下载，不再直接打开会被 Comet 拦截的 `chrome-extension://` 文件地址。
- Excel 模板已将输入区域设为文本格式，避免 USPS 等长物流单号被转换为科学计数法或丢位；数字单元格和科学计数法会被导入校验阻止。
- “发货导入”工作表的 300 行输入区域增加浅灰色完整单元格线，方便在 WPS、Excel 中横向和逐行录入。
- 插件会先切换到店小秘“搜索”模式，以订单号精确搜索，再调用订单详情接口做精确匹配。
- 搜索模式、搜索框或搜索按钮不可用时立即停止；搜索结果仍混有本批以外订单时也会阻止预检，不再扫描当前整页订单。
- 搜索收敛以店小秘页面显示的结果总数为准；固定列或隐藏表格产生的镜像行不会再被误判为额外订单，详情仍只回读包含本批订单号的目标行。
- 当页面同时残留旧分页总数和本次搜索总数时，优先采用与当前目标包裹行数一致的计数，避免搜索已收敛仍被旧计数阻止。
- 普通首次发货中，模板订单若已不在当前“待处理”页面，插件会将其标记为“已排除”并继续预检其余精确匹配订单；已排除订单不会进入任何发货请求。
- 预览明确显示导入、可发货和已排除数量；结果 CSV 同时保留已排除订单及原因。
- 预检会调用店小秘原生“不打单发货”选项接口，按订单平台读取当前可用承运商；输入物流商必须唯一匹配有效选项。
- 当前输入物流商支持 `UPS`、`USPS`、`FedEx`、`DHL`、`J&T`、`iMile`、`GOFO`、`SpeedX`，提交时仍以店小秘实时返回的精确名称为准。
- `iMile` 使用大小写敏感的严格映射：店小秘中的小写 `imile` 是另一个独立选项，不允许替代 `iMile`。
- 墨西哥站和美国站均按订单实时读取店小秘平台承运商；是否支持“不打单/导入发货”取决于店铺履约方式，不按国家统一拦截。
- 预览同时显示输入物流商和店小秘平台承运商；勾选风险确认并再次点击，才调用店小秘发货接口。
- 首次发货和拆单分批发货在最终预览页可通过“执行并发数”按钮选择 1–4，默认并发 2；单条明确失败不影响后续订单，结果可下载为 CSV。
- 店小秘返回繁忙时，当前批次后续请求自动降为串行；请求超时、断网或响应无法解析时立即停止派发新订单，已经派发的请求等待返回，剩余订单记为“未提交（已暂停）”。
- 发货执行期间实时显示完成进度、执行时长、初始并发、当前并发和接口繁忙次数；首次繁忙会记录对应预览行序号。
- 完成后的汇总固定显示在当前发货预览区，明确记录总执行时长、初始/最终并发、繁忙次数和首次降级序号，不再写入隐藏的拆单汇总区。
- 发货接口返回 `code=0` 只表示店小秘已受理，最终结果仍须到“发货成功/发货失败”列表复核。

第一期不接 Xynigo 云端物流查询结果，不自动读取采购系统，也不保存输入的订单号或物流单号。后续阶段再接入 Xynigo 物流结果并增加云端幂等审计。

## 输入格式

可以点击“下载导入模板”，在“发货导入”工作表填写三列后，再点击“上传 Excel/CSV”：

```text
订单号	物流单号	物流商渠道
GSH1TEST00001A	JMXTEST000000001	J&T Express
GSH1TEST00002B	49400000000002	iMile
```

模板上传要求三列均填写，物流商渠道支持 `UPS`、`USPS`、`FedEx`、`DHL`、`J&T Express`、`iMile`、`GOFO`、`SpeedX`。插件会在本地读取文件并统一为当前输入格式，不上传到 Xynigo 或第三方服务。

推荐从 Excel 复制两列：

```text
GSU1SAMPLE0001A	1Z999AA10123456784
GSU1SAMPLE0002B	1Z999AA10123456785
```

也支持逗号、分号或多个空格分隔。可选第三列临时覆盖本行物流商，例如：

```text
GSU1SAMPLE0001A	1Z999AA10123456784	UPS
```

普通首次发货模式仍禁止同一店小秘订单直接对应多个物流单号；需要多物流单号时使用“拆单分批发货”，由插件在确认后先完成 SHEIN 店小秘拆单。

当前每批最多 300 条，与店小秘列表单页可回读规模对齐。超过 300 条请拆分文件后分批操作，避免订单跨页后只回读到一部分搜索结果。

## 拆单分批发货

采购子单号是 Xynigo 业务字段，店小秘没有该字段。插件用它组织本批物流，但所有商品与店小秘包裹的关系仍要求采购按图片和规格人工确认：

1. 只录入本批已经拿到物流的采购子单；尚未出物流的子单不用填写，也不必等待。
2. 插件从采购子单号提取原订单号，搜索并回读当前包裹；若订单尚未拆开且商品总数大于 1，再调用店小秘拆单详情读取 `splitKey`、商品图、SKU/规格和数量。
3. 采购先选择子单，再点击对应商品并填写本次发货数量。插件校验每个商品累计分配数不得超过店小秘数量；未分配数量自动留在原包裹。
4. 勾选第一次不可撤销确认后，插件按原订单串行调用店小秘批量拆单接口；拆单请求不并发，也不自动重试。
5. 店小秘返回受理后，插件重新搜索并回读包裹；只有每个原订单的包裹数量与拆单计划完全一致才进入下一步，否则锁定本页并停止发货，要求人工核对。
6. 回读成功后，页面展示新包裹 ID、状态、商品图片和商品摘要。采购把子单映射到新包裹；同一包裹不能映射给两个子单，也不能跨原订单映射。
7. 映射完成后核对实时平台承运商并进入最终预览；采购需要第二次确认后才发货，发货阶段可选择 1–4 的受控并发数，默认 2。
8. 已经由店小秘拆好的订单会跳过拆单写入，直接进入包裹映射；未录入、未映射包裹保持不动，可等剩余子单出物流后再次处理。

拆单分批输入示例：

```text
GSH1SAMPLE0001A-1	JMXTEST000000001	iMile
GSH1SAMPLE0001A-3	JMXTEST000000003	iMile
```

上例只处理采购子单 `-1` 和 `-3`；`-2` 即使尚未出物流，也不会阻止本批发货。下载模板仍使用三列结构，在“订单号”列填写采购子单号；上传文件也接受表头“采购子单号”。

## 安全边界

- 只匹配 `dianxiaomi.com/web/order/approved*`，并在运行时再次校验路径必须为 `/web/order/approved`；不申请 Cookie、全站网络或后台监听权限。
- 订单必须通过店小秘 `/api/order/detail.json` 回读并与输入完全一致，不能只凭列表文本模糊匹配。
- 必须通过 `/api/order/withOutPrintShippingList.json` 读取订单所属平台的实时承运商选项；不再把 `J&T` 硬编码为猜测名称。
- 平台承运商匹配失败或同时命中多个候选时阻止提交，并显示店小秘返回的候选名称。
- 只有“当前待处理页面未找到”可以安全排除；搜索混入其他订单、同一订单匹配多个包裹、详情回读失败或平台承运商无法唯一匹配时仍然整批阻断。
- 不按订单国家猜测店铺履约能力；团队已验证的商家自履约店铺继续使用“不打单/导入发货”流程。
- 执行前必须预览，并勾选“已核对且确认不可撤销写入”。
- 自动拆单当前只对店小秘明确返回为 `SHEIN` 的订单开放；其他平台阻止拆单。
- 拆单计划必须人工核对采购子单与商品图、SKU/规格和数量；插件不根据子单序号猜测商品。
- 拆单按原订单串行执行且不自动重试；任一超时、断网、无法解析或拆后包裹数量不一致都会停止后续拆单和发货，防止重复拆包。
- 拆单完成后仍必须人工完成采购子单与新包裹的一一映射；插件不根据接口返回顺序猜测映射。
- 首次发货和拆单分批发货并发数仅允许 1–4，默认 2；仅对店小秘明确返回“正在执行移入运单号申请”做有限重试，并在繁忙时自动降为串行。
- 网络中断或响应无法解析时标记为“结果未知”，不自动重试并停止派发剩余订单；未派发订单会在结果 CSV 中标记为“未提交（已暂停）”，须先去店小秘已发货列表核对。

## 复用来源

- 发货接口与参数流程来自前 IT 在 2025 年维护的 `dxm_super_logistics_tool`。
- 发货窗口批量填号思路参考现有 `scripts/dxm-ship-without-order/`。
- 本插件移除了旧深孚账号、密码、第三方物流中心、广泛主机权限和高并发逻辑，改为本批手工输入、精确预检与显式确认。
