# Xynigo 店小秘运营采购助手安装说明

当前线上运营测试版：`0.12.1-standalone-cloud-login-test`，GitHub Prerelease 标签为 `dxm-purchase-assistant-v0.12.1`。

## 使用条件

- 运营电脑只需要安装 Chrome/Edge 扩展，不需要启动 Xynigo 本机服务，也不需要先登录 Xynigo 网页。
- 扩展通过飞书完成一次独立登录，随后直接访问 `https://xynigo.samforo.icu`。
- 飞书 App Secret、飞书访问令牌和云端数据库凭证均留在服务端，不写入扩展。
- 扩展只在浏览器会话内保存短期 Xynigo 会话；浏览器重启、扩展重载或会话失效后需要重新登录。
- 本机 Xynigo 服务仍用于开发联调和 HubStudio 本地环境执行，但不是运营提交采购单的前置条件。

## 加载本地联调版

1. 在本扩展目录执行 `sh build.sh --dev`。
2. 打开 `chrome://extensions/`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 `dist/xynigo-dxm-purchase-assistant-dev`。
4. 确认版本号为 `0.12.1`；扩展版与油猴版二选一，不要同时启用。
5. 修改或重新加载扩展后，必须刷新已打开的店小秘页面。

## 从跨境插件仓库安装

1. 打开 GitHub Release `dxm-purchase-assistant-v0.12.1`。
2. 下载 `xynigo-dxm-purchase-assistant-v0.12.1.zip`，解压到固定目录。
3. 打开 `chrome://extensions/`，开启“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择解压后的同名目录。
5. 确认版本号为 `0.12.1`，工具栏显示“精准匹配”放大镜图标。
6. 以后升级时覆盖固定目录、在扩展管理页点击重新加载，并刷新已打开的店小秘页面。

## 首次登录

1. 打开扩展弹窗，点击“使用飞书登录”。
2. 在新页面点击“继续飞书登录”，完成飞书授权。
3. 授权成功后，扩展登录页会自动关闭；若浏览器拒绝关闭，会显示手动关闭提示。
4. 重新打开扩展，确认当前成员、组织和采购提单权限。
5. 若账号缺少 `procurement.request.save` 或 `procurement.request.submit`，由管理员在 Xynigo 云端分配权限；无需向运营开放 Xynigo 页面。

扩展不会要求运营粘贴 Token，也不需要扫描 `127.0.0.1` 端口或进行本机配对。

## 提单验收

1. 打开一张经授权的测试订单和“采购明细”页签。
2. 核对商品、订单商品图片、销售数量、币种、站点、店铺/运营以及预估金额。
3. 点击“保存采购单”，应显示云端草稿保存成功，编辑页保持打开。
4. 补齐每条明细的精确采购链接、指导价和数量，点击“提交采购单”。
5. 只有云端正式提交成功后，插件才切换到店小秘原生“备注信息”选项卡、打开客服备注并预填 XYP2；插件不得自动点击店小秘“保存”，流程结束后订单详情应停留在“备注信息”便于核对。
6. 云端认证或提交失败时，只保留可重试状态和剪贴板兜底，不打开、不填写客服备注。
7. 同一订单正式提交成功后，只允许生成一条新的 XYP2 客服备注；重复点击、网络响应丢失后重试或重新打开订单，都不得追加第二条。
8. XYP2 超过当前字符上限时必须阻止提交，不能写入截断文本。
9. 正式提交后、采购尚未认领时，重新打开采购明细应显示“提交修改”；修改成功更新原采购单版本，并在唯一 XYP2 客服备注存在时自动编辑、提交和回读，不新增备注。采购已认领或开始执行时必须拒绝直接修改。
10. 找不到 XYP2、存在多条 XYP2、编辑内容发生变化或回读失败时，插件必须停止备注自动修改，显示明确原因并保留新版 XYP2 剪贴板兜底；再次点击“提交修改”可以只重试备注同步。

`syncStatus=pending` 只表示云端已生成待同步事件，不代表飞书表格已经写入成功。

## 常见问题

- “云端认证请求失败”：先打开扩展弹窗查看登录状态；若会话失效，重新执行飞书登录后再提交。失败期间不会写客服备注。
- “Xynigo 请求失败（403）”出现在飞书登录发起阶段：确认使用最新开发包并重新加载扩展；旧包可能携带 Xynigo 网页 Cookie，被云端 CSRF 保护拒绝。
- “已登录，但缺少提单权限”：联系管理员分配采购保存/提交权限，不需要安装本机服务。
- 页面提示扩展上下文已失效：重新加载扩展并刷新店小秘页面。
- 登录窗口被拦截：允许当前扩展打开新窗口后重试。
- 已正式提交后需要纠错：未认领时使用“提交修改”；已经认领或开始执行时，先由采购在 Xynigo 退回任务，再修改。

## 发布与更新边界

当前不使用 Chrome Web Store。GitHub Release 可用于统一下载和版本留档，但“加载已解压的扩展程序”不会自动更新。现阶段升级方式仍是下载新版、覆盖固定目录并在扩展管理页重载；不得把 GitHub Token 或任何长期更新凭证放入扩展。

历史 Prerelease `0.11.1` 仍依赖 Xynigo 本机桥，不满足“运营只安装插件”的要求；运营独立使用必须安装 `0.12.1` 或更高版本。
